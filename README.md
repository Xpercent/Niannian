# 拾光 · 微信消息与智能待办

把真实微信消息整理成可追溯的行动清单。基于 Windows 本机微信 4.x，只读采集消息与已下载附件；使用关闭思考模式的云端模型提炼，保留原文、过滤依据和每次变更。

这是 project4 的架构重构版本，独立开发于 project5，参考工程保持原样。没有演示消息播种，也没有手动消息录入入口。

## 启动

环境：Windows、已登录的微信 4.x、64 位 Python 3.10+（本机验证为 3.13）；Node.js 用于前端验证，运行应用无需 Node 或前端构建。

```powershell
cd E:\Group\Desktop\Code\wx\project5
.\scripts\setup.ps1
.\scripts\start.ps1
```

打开 http://127.0.0.1:8765/ 。当前工作区已有实际连接配置、真实消息数据库和初始化后的微信依赖，可以直接运行启动命令。

全新检出先执行 `git submodule update --init`（setup 会执行），模型配置可从 `config.json.example` 复制到 `config.json`，或在界面「设置与数据」中填写。API Key 按要求以明文保存在本地配置。模型请求始终发送 `enable_thinking: false`。存储路径修改需要重启；一般设置下一轮生效。`start.ps1 -NoWeChat` 仅供离线查看已保存数据。

## 使用流程

1. 「微信会话」选择真实会话，打开关注；新会话默认不关注。关注后读取最近历史，可以再次导入最多 1000 条，自动去重。
2. 在「我的画像」写准确的身份、职责和参与意愿。画像为空时，条件活动邀请或指定他人的职责通知留在过滤记录中等待复核。
3. 点击「立即提炼」，或者等待自动轮次。运行中显示真实进度，支持取消；没有处理完的消息保留在队列。
4. 在待办清单筛选、编辑、完成或忽略事项；打开详情查看完整来源、附件及变更。忽略事项可以恢复。仅有明确本人身份的完成消息才会自动核销任务。
5. 查看过滤记录，按需要调整规则与画像。导出 JSON/Markdown 或创建一致性数据库备份。

关闭会话关注仅暂停提炼；已经选择的会话继续采集，重新关注后可以继续处理。采集不会发送微信消息或驱动微信下载附件。

## 架构

采用模块化单体：一个本地 FastAPI 服务、SQLite WAL 仓储、一个串行微信读取线程、一个提炼协调器和无需打包的 ES Modules 前端。避免旧版多个监听/HTTP 桥接/全局状态的并行补丁。

| 模块 | 职责 |
| --- | --- |
| `shiguang/wechat.py` | 上游只读适配、账号隔离、串行命令、可靠采集水位及身份证据 |
| `shiguang/media.py` | 解析真实附件并定位已下载本机文件 |
| `shiguang/storage.py` | 消息与水位原子持久化、来源幂等、UTC 索引、任务版本与审计、一致性快照 |
| `shiguang/engine.py` | 聚合、公平有界队列、指令执行、保守回退、本人身份约束 |
| `shiguang/llm.py` | OpenAI 兼容请求、紧凑上下文、结构验证与业务闸门 |
| `shiguang/jobs.py` | 定时/手动单轮提炼、持久化进度、取消和退出恢复 |
| `shiguang/config.py` | 类型化配置、文件原子保存、单轮快照 |
| `shiguang/api.py` | 应用工厂、显式生命周期、薄 HTTP 接口 |
| `shiguang/web/` | 全新亮色工作台、来源抽屉、会话/规则/画像/设置 |

微信采集先提交原始消息与水位，再交给提炼。任务编辑带版本号，冲突返回 409，避免模型覆盖用户编辑。每轮最多 240 条、每会话最多 80 条；余下内容继续排队。模型每批最多 4 个聚合段并限制上下文预算，失败时仅从完整明确动作保守降级，复核原因可回查。完整 API 见 `/docs`。

## 已知边界

依赖本机微信登录状态、Windows 和上游微信数据库适配，客户端升级可能需要同步更新适配器。只处理文字及附件说明，不做图片 OCR、语音转写，也不会自动下载未落地媒体。模型结果需要人工判断，缺失画像和角色不清的通知会保守留待复核；历史已过期事项仍按原文保留，用户可忽略。过滤记录每会话保留最近 100 个判定。服务默认只监听本机，定位为个人工作台，未实现多用户协作或移动端服务器。
