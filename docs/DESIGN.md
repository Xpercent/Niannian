# 念念界面设计与交互

更新日期：2026-10-12。本文描述当前 React 界面；早期原生前端截图与评分见 VISUAL-REVIEW.md，仅作历史参考。

## 方向与实现

个人微信待办工作台，主任务是查看行动、回查原消息、编辑或完成事项。沿用用户选定的亮色白/灰绿工作面与森林绿主动作，不改深色、不用视觉重做掩盖后端问题。会话、任务、来源和统计来自实际 API，不播种演示数据或虚构成功状态。

前端采用 Vite + React + TypeScript，Tailwind CSS 管理布局与样式，shadcn/ui 本地组件管理基础控件，Recharts 管理图表，lucide-react 管理图标。统一主题在 `niannian/web/src/styles.css`，当前背景 `#f6f8f6`、工作面白色、主动作 `#246448`，字体为 Segoe UI / Microsoft YaHei UI / PingFang SC。不再以旧原生前端的精确字号、布局或动画时长作为当前实现保证。

桌面使用左侧导航与右侧工作区；手机通过顶部菜单打开导航，表单自然换行，来源抽屉适配窄屏。保留标准控件键盘访问、aria 与焦点管理、reduced-motion；用户要求移除的应用快捷键与命令面板不恢复。

## 页面与状态

| 页面 | 用户任务与关键行为 |
| --- | --- |
| 待办中心 | 搜索、状态/优先级/会话/期限筛选，编辑、完成、忽略和恢复；业务事实以 API 为准 |
| 来源抽屉 | 完整原文、真实本机附件、任务事件与上下文；编辑携带 version，409保留输入，不自动覆盖 |
| 微信会话 | 真实目录、关注/暂停、历史导入、消息分页与过滤记录、单会话提炼；暂停不停止已选会话采集 |
| 提炼诊断 | 轮次追踪/调用检索/异常与拦截/滞留队列四个视角；选中轮次看模型调用序列、落库变更与按原因归类的无需行动；选中调用看“发给模型的内容”“模型回了什么”“校验改写与落库结果”“原文对照”；无样本显示“—”，不补造趋势 |
| 规则 | 名称、表达式、说明与动作配置，表单失败保留输入；规则不能绕过业务校验 |
| 我的画像 | 编辑并保存真实身份/职责/意愿，不猜身份；提炼完整使用画像 |
| 设置与数据 | 模型配置、常用提炼时间、高级参数、微信控制、导出与一致性备份 |

设置页常用项只有自动提炼间隔和等待补充消息，其他参数默认折叠在原生 details 的“高级设置”，折叠不卸载输入。正文预算解释分批、压缩目标解释长文总结；不再提供每次请求段数、单轮/单会话消息上限、个人背景长度参数。保存后读回 API，恢复默认值仅填入草稿，保存后生效；Key 留空保留既有值，响应不回显密钥。仅显示“已配置”不代表本次连接探测成功。

诊断台用于回答“到底给模型发了什么、模型回了什么、为什么没落成待办”，不用于展示装饰性图表：旧的耗时柱状图与每日汇总表已随该页重写移除，待办中心的图表保持不变。检视器把请求体拆成系统指令、本次新段落、历史参考、已有待办、个人画像与原始 JSON 六块，逐段标注字符数与预算占用，出现截断标记时明确提示模型没看到中间内容；响应侧保留未去代码围栏的原文与解析后 JSON，`finish_reason=length` 与接近输出上限会给出告警。校验对照按段落并排显示“模型返回”和“校验后进入事务”，只在 RESOLVE 显示核销结果，其他动作的默认 resolution 不显示成已完成。身份确认徽章只作用于本人消息。列表行不返回请求正文，正文只在打开单次调用时读取。用户于 2026-10-12 要求完全重写该页并以分析数据为目标。

采集、提炼、加载、保存的成功/失败均跟随实际响应。提炼轮询真实 run，取消请求不等于立即中断网络请求；最终状态由服务确认。进度中的 skipped 可能是暂缓/失败留存，不等于消息删除或任务忽略。CREATE 不显示 resolution；RESOLVE 才显示完成/取消，MERGE 使用中文业务文案。

## 维护与验证

保留现有组件和主题，不另造设计系统或叠覆式CSS补丁。前端源码按 `src/pages/`、`src/components/`、`src/lib/` 分工，修改后执行 `npm run build`；按需 `npm test` 验证附件路径与上海时间工具，不能把旧JS语法检查当TS验证。

实际页面检查按变更选桌面/手机、必要状态、无横向溢出、失败保留输入、保存读回、焦点与附件来源。未实际执行的写入或端到端操作必须说明，不能从截图推断全部功能通过。近期设置页折叠/展开与桌面/手机只读截图在 `artifacts/settings-simplify-*`，未真实保存设置；早期首页评分不代表当前整站评分。

2026-10-12 诊断台重写后的界面检查：先用一次性工作区（一致性备份副本、`--no-wechat`、独立端口）跑真实云端一轮产生 4 次批量调用，逐屏确认轮次列表、调用序列、请求/响应检视、校验对照、检索过滤与空队列状态，无横向溢出；随后在 8765 正式实例确认同一页面读取真实数据。该轮截图未能保存——内置浏览器可视化面板当时不可用，只留下结构化 DOM 检查证据，因此视觉细节（尤其宽屏双栏对齐）仍需用户目视确认。

`design-directions.html` 保留早期选型素材，不是当前实现截图，也不构成重做界面的任务。
