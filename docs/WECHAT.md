# 微信只读采集

当前采集与身份约定；其中真实验证数字只描述验证当时。提炼调度、长文总结与云端失败留存见 HANDOFF.md / ARCHITECTURE.md。

本系统只读取本机登录微信的数据库和已下载附件。`WechatWorker` 不调用或驱动 GUI 自动化，不注册上游多线程 Listener，不发送微信消息；上游包导入可能传递加载 GUI 模块，本机未下载的媒体不会驱动微信界面下载。

## 串行与账号隔离

所有上游读取发生在一个 `wechat-reader` 线程。API 调用 `catalog()` 和 `import_history()` 通过请求队列与 Future 进入该线程。`start()` 异步连接，状态依次为 `starting`、`connected`，失败时报告 `error`；`stop()` 等待当前读取退出，并释放独占锁。

解密缓存位于 `data/wechat/cache/<账号目录 SHA256 前16位>/`。独占锁覆盖整个 `data/wechat/cache`。适配器约束上游账号自愈时的 `workdir`、`keys_file` 和稳定密钥副本，避免其回落到其他工程使用的系统临时缓存。可以只读复用既有密钥缓存；所有新解密结果与密钥副本均写到本工程目录。上游源码保持原样。

会话主键为 `wechat:<微信账号 SHA256 前16位>:<真实 username>`，并保留 `sessions.account` 与 `sessions.username`。消息去重键同时包含账号和真实会话；存在有效服务器消息 ID 时使用服务器 ID，否则使用原始消息的 sort_seq、local_id、创建时间与内容。媒体和媒体索引也按账号隔离。

## 历史、暂停与可靠水位

目录中的新会话默认不监控。只有明确选择监控或已经执行历史导入的会话进入采集选择集。关闭监控只暂停待办提炼，已选会话仍保留消息采集。

每轮同步目录，然后对所选会话读取最新消息，并向旧消息分页，直到越过已保存水位。水位边界本身会重复读取，因此同 sort_seq 的消息不会因边界相等而遗漏，重复消息由源键去重。恢复运行后依照持久化水位补齐停机期间消息。

`Database.ingest_batch(messages, checkpoint)` 在同一 SQLite 事务内插入消息和推进 `wechat_checkpoints`。任意消息写入失败会整体回滚，水位不前进。历史回填不能降低已有水位。初次选择会话导入配置中的最近 `history_limit` 条，更早内容可再次执行历史导入。

微信文件晚于消息落盘时，重复扫描通过 `attach_media` 合并真实附件路径和档位，仅修改 metadata_json；不覆盖已挂文件，不改正文、processed和水位。同一 metadata 中的 text_compression 是提炼层总结缓存，不是微信原文；身份判断始终依据原始信息。

## 发送者与本人标记

2026-10-12 用户明确要求完全移除身份确认设计，只保留 `is_self`。当前采集优先使用群消息正文的真实发送者前缀，以及附件 XML **根节点直接子项** `fromusername`；没有这两类账号时，回退上游 `sender_username`。引用消息的内嵌 `refermsg` 不参与读取发送账号。选出的发送账号与当前微信账号一致时设置 `is_self=true`；数字 `sender_id` 不用于判定本人，包括数字 2。

`identity_source`、`identity_confident`、`identity_conflict` 已停止生成和使用，已验证数字 ID 映射也不再读取、更新或参与采集。历史 metadata 与 runtime 映射保留原样，不清理正式数据。后续业务只使用 `is_self`，没有额外身份可信门槛。

消息 metadata 仍保存原始索引用户名 `source_sender_username` 和原文发送账号 `origin_sender_username`，保留可追溯信息。名称仍通过账号名称表显示备注或微信昵称，当前读取接口没有提供群昵称。正文完整保存，不再按 19000 字截断。

缺少原文发送账号时，`is_self` 取决于上游账号字段，取消了旧映射策略提供的交叉验证；不把名称显示正确作为账号索引始终正确的保证。

## 本机验证记录（2026-10-09）

连接真实微信后发现 81 个会话，20 个数据库均有可用密钥，无缺失密钥。隔离缓存路径校验通过。

原始真实捕获共 569 条、25 个会话。该历史捕获中有 23 条按当时索引或 ID 2 看似本人，但与群正文权威发送者冲突；当时版本按权威来源保留他人身份。原始捕获中另有 12 条明确本人来源，验证出非标准数字 ID 5。这些数字是历史样本结果，不是当前运行数据统计。

现场通过新 worker 选取包含明确本人来源的 3 个实际会话，导入 195 条真实消息，其中 91 条按权威来源或经验证会话数字映射识别本人。保存 3 个水位，再次历史导入得到 195 条重复、没有新增重复记录。本机媒体提取可用。该验证使用临时应用库，未替用户启用任何会话监控，测试后采集线程已停止并释放缓存锁。

上述本人识别统计采用当时的原文账号与已验证数字映射策略，2026-10-12 已按用户要求删除后者，不能把旧统计作为当前策略的验证结果。

`tests/test_wechat.py` 使用真实原始捕获测试原文发送账号优先、缺少原文账号时的上游字段回退、旧确认字段不再生成、账号隔离、目录默认不监控、去重、消息失败水位回滚、暂停后续采与重启补漏、附件摘要和独占锁。不会编造聊天内容。2026-10-12 本次验证为 15 passed；现有捕获无“缺少原文账号且上游账号为本人”的样本，未验证该回退分支的真实本人识别。
