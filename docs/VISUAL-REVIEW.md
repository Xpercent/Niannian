# 主页面独立视觉评审

> 历史资料：本文记录早期原生前端的独立评审与复评。前端已按用户要求替换为 React/TypeScript；以下分数、坐标与动效证据不代表当前界面，也不是待自动执行的改善任务。当前界面约定见 DESIGN.md。

评分：**7 / 10**。这是以微信消息为来源的个人任务工作台；亮色、安静的绿色方向成立，也明确呈现了任务列表，但首页仍偏向通用仪表盘，真正需要处理的任务出现得偏晚。离 8 分还差：提高任务首屏密度，强化“智能整理后的行动”与来源的层级，并补齐操作动效证据。

范围：仅依据 1440×1000 与 390×844 的当前主页面截图；未读取实现代码，未验证详情、设置、真实操作或异常状态。截图中的个人身份及消息正文不在本报告复述。

## 三项最高优先改善

1. **把待办提到首屏更靠前的位置。** 桌面第一条任务约在 y=516，手机约在 y=551；手机在 844 高度里只完整看到三条，顶部四块统计占去约 150 像素。工具类标杆通常把可操作对象放在标题和紧凑筛选之后。建议手机把统计压成一行或仅突出逾期与待处理，桌面把重复统计收为紧凑指标；删除英文眉题，压缩标题说明区域。调整后检查 390 宽首屏能完整看到至少四至五条任务，筛选仍可触达。

2. **让任务标题体现整理后的行动。** 当前可见行包含广播标记、聊天用语、表情或其他消息痕迹，读感接近原消息摘录，智能待办的价值不够清楚。建议主行使用短、明确的行动句，把原文留在详情；截止日、优先级、任务状态放到稳定位置，来源群名保留为次级可点击线索。已有来源标签和行尾箭头可以保留。检查应能在扫描中迅速判断“做什么、何时做、来自哪里”，并在详情里对照原文确认，没有凭空补充期限。

3. **增强关键状态与小字的可读性。** 逾期、高优先级和普通任务之间的视觉差异很弱；手机来源、日期、统计标签与控件文字显得过小，浅灰与浅绿正文也容易被白底吞掉。建议移动端次级文字至少 12px、关键状态至少 12–13px；只给逾期和高优先级更清晰的颜色与文字对比，保留大面积中性背景。检查实际尺寸下无需放大即可读来源和日期，正文达到 4.5:1 对比度，紧急任务能先于普通任务被看到。

## 可以保留

- 亮色画布、深绿主操作、克制的线性图标，适合长时间处理工作。
- 桌面“导航—任务—辅助信息”结构，列表分隔与行内完成入口清楚。
- 手机保留任务视图与筛选，没有把主任务变成营销内容。
- 同步状态、提炼进度与取消入口，以及每条任务的来源线索。

## 必须补齐的验证

主操作反馈、一次状态切换、首次进入出场均未交动态证据。属于“没交”，不能据此断言页面没做；也不能宣称交互已通过。请各补一段 3–5 秒录屏或开始/中间/结束三帧，并写明触发动作，检查反馈从被操作对象产生、状态变化可理解、进入动效不拖慢处理任务。按新界面协议，当前证据不足时总分上限为 8 分。

右侧今日概览与顶部统计有重复，可在密度调整时合并；说明性小字不必为了填满区域保留。静态截图未观察到明显重叠或横向溢出，但手机下方内容与详细流程不在本次验证范围内。

## 早期交付画面独立复评

**最终评分：8 / 10。** 当前画面达到清楚、可信的个人工作工具水准。依据 `artifacts/ui-final` 的桌面与手机截图，以及三组 `motion-start/mid/end.jpg`，未读取实现代码。真实数据只有两项不是缺陷，不建议用演示任务填充画面；正在新增的待提炼数量也不按失败处理。

手机首条任务约在 y=385，两项真实任务都完整进入首屏，完成入口、来源和日期有分层；行动句简短，主内容与来源消息之间的职责更清楚。桌面列表、筛选、侧栏与主按钮对齐稳定，没有观察到明显重叠、截断或横向溢出。深绿主操作、安静的亮色画布、抽屉内原始来源及图片依据值得保留。

剩余差距按优先级排列：

1. **小字与状态对比仍偏弱。** 手机的统计标签、来源、日期、筛选及列表底注显得小且浅，普通优先级标签尤其细小。建议把必要元信息提升到实际可读的 12px 左右，增强文字对比；检查实际手机尺寸及正文 4.5:1 对比度。不能仅凭截图确认字号或精确对比数值。
2. **低任务量时，仪表盘结构仍比任务本身重。** 四块统计与今日概览重复同类信息，列表最后一条和底注之间仍留有明显空段。可按内容收缩列表最小高度，将概览简化为异常提醒；桌面英文眉题可直接删掉，底注提示只在首次使用时出现。检查两项任务时画面自然收束，多项任务时仍有稳定扫描密度。
3. **主操作动态证据仍有一项范围缺口。** 进入组显示加载到内容，抽屉组显示列表到来源详情，来路清楚；刷新组出现按钮反馈和刷新通知，能证明辅助操作反馈，但不能证明“立即提炼”及任务完成的反馈。应补一段实际主操作的开始、处理中和结果证据，确认反馈来自触发处、结果数字与列表一致。这里属于“没交对应证据”，不据此断言没有实现。

三组动作保持克制，适合日常工作工具；静态状态中的记忆点来自“短行动项连到原始消息及图片证据”。现有三帧足以确认状态来路，无法据此判断完整时序、持续时间、触感或手机抽屉操作。报告 JSON 仅有终帧及空问题数组，没有完整动画探测信息。离 9 分还差精简重复信息、提升元信息的阅读舒适度，以及把主操作与手机详情的证据补完整；本次不宣称全部流程或异常状态已通过。

主操作证据补充：已查看新增 `artifacts/motion-process` 三帧，“立即提炼”触发后出现进度区域与开始通知，主操作的启动反馈已有证据；中帧及终帧仍显示处理中，因此三帧不能证明完成结果（队列为零不是故障），任务完成反馈与手机详情仍未纳入本次验证，评分保持 **8 / 10**。
